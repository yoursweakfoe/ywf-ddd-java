# changes/ —— 修订工作区（框架法案）

> 本区受理**框架/脚手架行为**的法案；业务包的法案立到镜像区 `sample-application/specs/changes/`（模板共用本区 `_template/`）。

一个变更 = 一个目录：`<YYYY-MM-slug>/`，内含四件套。从 `_template/` 复制起稿，套立案当天现行模板的形状；模板日后改版，不回改已立案的旧卷。四件各司一职：

1. `specify.md` —— 说清做什么、怎样算做成：Why / What changes / 验收 AC 账 / 约束 / 不做 / 裁决问句。末节 **§裁决记录** 是决策事件、当时理由、门次收据的唯一居所：裁一条落一条，落笔后不改写。本件零实现细节、零法条正文。
2. `plan.md` —— 说清怎么做、改哪些法。技术决策按 P-x 编号，含被拒方案与拒因；修卷 delta（ADDED / MODIFIED / REMOVED，SHALL + GIVEN/WHEN/THEN）是**法条正文唯一居所**，每条标 ← AC-n；再加波及面与回退。
3. `tasks.md` —— 纯执行清单。每条是一个可验收动作，条内不写设计参数，指 P-x 编号即可，末尾指 AC-n。
4. `implement.md` —— 执行账本：完成即勾、取证、AC→证据映射、delta 源回填、漂移回门、收官闸。

**三写禁绝**。它是宽严双份制在案卷内部的镜像，规则是每类文字在同一个案卷里只有一个住所：问题住 specify 前段，裁决住 specify §裁决记录，条文正文住 plan，执行账住 implement。其余位置只准出现 AC-n / P-x 指针。
**两道批准门**，先 Specify 门后 Plan 门。每案两停，不论案之大小。法面不设并审或豁免条款；放行只出自会话中项目主的明示指令（→ 案卷 2026-09-sdd-four-stage §裁决记录）。

**折叠即修法**。实现完成、implement 账清之后动手：账清指每条 SHALL 的取证源已回填为真实的 文件:行 或测试名。然后把 `plan.md` 的修卷 delta 合入 current 对应节，本目录整体移入 `../archive/`，date-slug 命名，入档后只进不改。唯一例外：**清册 bill 不折叠**。执行卷宗清册的案卷在末步整删自身目录（自焚），三区零残留才算合格。法源见归属法 §4「卷宗清册执行」行。
折叠那一刻，是该变更全部文档同步义务的唯一发生时点（归属法卷 §4）。在此之前，本目录是草稿，`current/` 是现行法；两者不一致时以 `current/` 为准，代码违规就去修代码。
