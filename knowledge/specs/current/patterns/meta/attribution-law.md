# 用法规范法卷：归属法（知识系统元法 · 严格件）

> **身份**：本卷是知识系统的宪法。核心只有一条——**每类事实恰好有一个权威住所，其他所有地方只准写"一句规范 + 路径指针"**。它管的是文档和代码的维护行为本身：违反就按本卷裁决去修放错地方的那份。
> **本卷也是法**：它住在 `specs/`，改它要走和改别的法卷一模一样的 `changes/` 立案程序。体系里没有免修于程序的宪法。（前身是 `.agents/rules/05`，2026-10 法律入典改革升格至此。）
> **机器对账**：本卷各条的判据由 `knowledge/scripts/check-docs.ps1` 七校验执行，说明见 [docs/reference/doc-guards.md](../../../../docs/reference/doc-guards.md)。

## 1. 诸区分野（一目录一法律）

| 位置 | 性质 | 真相源 | 冲突时谁改 | 何时写 |
|---|---|---|---|---|
| `knowledge/docs/` | 描述（地图） | 代码 | 与代码不符 = 文档是 bug，改文档 | 代码之后，被动跟随 |
| `knowledge/specs/` | 框架契约（法律） | 意图/约定 | 与代码不符 = 二者之一必修；改法必须走 `changes/`，禁止迁就代码偷改 | 代码之前，主动发起 |
| `sample-application/specs/` | 契约镜像（业务法） | 意图/约定（生意） | 同框架法；业务名只在这棵树合法——契约描述生意，教学描述通识 | 代码之前，主动发起 |
| `.agents/` | 流程（SOP） | 不适用（约束 worker 的手法） | 不腐烂、不被违反，只被执行。**法不住本树**——2026-10 法律入典后本树只剩 skills；根 AGENTS.md 的九条是唯一合法的压缩复述位 | 观察到犯错后追加流程步骤 |
| `knowledge/scripts/` | 执法（工具链） | 不适用（守护事实，不描述事实） | 文档红 = 修文档或修工具，按磁盘实证裁决；说明书唯一入口 = `docs/reference/doc-guards.md` | 随探测器演化 |

三区分立的原则：

- 伞 `knowledge/` 和区 `docs|specs|scripts` 自身都不立法。方法树 `.agents/` 拒绝入伞——工具可弃，知识与契约不可弃。执法工具链放在伞内 `knowledge/scripts/`（2026-09-06 内聚裁定）：它的辖域是"每区各自的法律"，而不是物理上挨着谁。
- 两区必须分家的原因：地图区的守则"烂了修文档"是溶剂，法律泡在里面会被顺手改掉。所以每区的法只在自己目录生效，互不相犯。

**过程件与沉淀件，两类件分家**：

| | 是什么 | 住哪 | 生命周期 |
|---|---|---|---|
| 过程件（案卷） | 立法过程：问题陈述、验收账、**裁决事件与当时思考的快照、批准收据、supersede 宣告**（全在 specify §裁决记录——案卷级裁决唯一居所）、技术形状与条款变化量（plan）、施工清单（tasks）、执行账（implement） | `specs/changes/`（审议中）→ `specs/archive/`（折叠后整袋迁入） | 折叠即使命终；入档只进**不改在位**；到期整册抹除（见下"卷宗清册制"） |
| 沉淀件（论证现行版） | "这部法**今天**为什么成立"的完整论证 | `docs/explanation/` | 永续。折叠时刻（⑨⁺）强制从案卷复写进来，篇脚回指 `→ 案卷 <date-slug> §裁决记录（决策快照）`；清册时快照随册灭，论证留下（行灭理存） |

两处都写论证不是双写：**案卷 §裁决记录回答"当时怎么定的、谁批的"（冻结收据），解读篇回答"今天为什么如此"（活体现行）**。时效语义不同，执法闸也不同（C6 冻结臂护前者不被涂改，§4 同步义务护后者不腐烂）。沉淀件必须先于过程件独立成立——这就是自足判据。旧病灶是裁决同时写在案卷和独立判例区（ADR），近同文两份；判例区撤销并入案卷后，裁决只剩一个家。

**卷宗清册制**（案卷到期彻底抹除，项目主裁定基调；2026-09 判例归卷案把清册面收缩为案卷两袋）：两侧 `specs/archive/`（含镜像区，合称**两册**）是**可清册存储**，不是永久档案馆。于发布节点或项目主宣告时，由一支独立的清册 bill 执行彻底抹除：

- 本体整袋删除——禁拆件、禁在位改、禁择留；README 的账行同裁（README 常驻的是章程，不是账目）；活面全部具体案名（date-slug）净空——改写为无编号散文或整行删除。
- 旧 `ADR-NNNN` 编号制已随判例归卷废止；`ADR-` + 四位数字在活面**常设零容忍**（C6 直接红），不依赖清册触发。
- **自足判据**（先验门槛）：抹除前，每案的四栏因果——立因、取舍、被拒方案及拒因、生效边界——必须已完整住进 `docs/explanation/` 或 `current/` 条文。一句话检验：**一个从未见过卷宗的读者，能从解读架复述该案全部因果**。过不了就先补沉淀，缺节不得批准清册。清册后存活的只有两样：解读架的因果全文 + current/ 的现行条文。
- git 历史**不算**存活件，也不是任何层的依赖：知识的权威面永远在工作树，法不考古。
- 清册 bill 自己也是案卷：**自焚**——末步整删自身目录，不折叠、不落 §裁决记录（执行不是裁决事件），三区零残留才是合格终态。仪式产物不豁免于仪式。案册归零即重启案数（编号制已废；案名 date-slug 惯例不变）。
- 机器执法（C6 两臂）：冻结臂 = 案卷本体在位被涂改则红；清册臂 = (a) 整袋删除仅在自称"清册 bill"的在途案卷下放行，且删后该册必须归零；(b) 废号零容忍 + 两册空而活面仍残留 date-slug 案名则红。

| 任务流程（顺序 + 清单） | 低 | `.agents/skills/`（≤500 行） | 法卷指过来。**skill 内零法条零模板**（D6 推广）；形状性内容必须锚定法卷某卷某节（实施内容基准律，见下表注） | C2/C3 + ddd-review 锚点抽查 |
| 防腐工具行为与用法 | 中 | `knowledge/scripts/` 代码本体（行为即法）+ `reference/doc-guards.md`（说明唯一入口） | 一行 + 指针 | 人肉跑主机 + ddd-review 末步 |
| 术语 → 身份定位 | 中 | `docs/reference/glossary.md`：只准"一句定位 + 指针"，禁定义复述 | 指针 | — |
| 法卷摊归属与摆架判据（摊地图、牌面、空穴登记、搬家账） | 低 | `specs/current/patterns/meta/pattern-taxonomy.md` §2/§3/§4 ＋ 目录路径本身（摆架卷 meta-2：路径即名册） | 一句守则 + 指针（specs/README 目录表、伞 README 树行、摊头牌面）；禁复写摊卡正文 | 评审项（ddd-review 新卷归摊） |
| 元法（本卷：事实归属本身） | 低 | 本卷 | 一句守则 + 指针（伞 README / docs README 各留一行） | — |

**易变性分层**：低易变的教义就近重述是有益冗余；高易变的事实重述是纯债——只禁后者。

**实施内容基准律**（2026-09-07 用户裁定）：单一事实源不止"禁止抄法"（D6 负面义务），还要求——skill 与 docs 内一切**可机械化内容**（代码形状、包结构位、注解、签名、文件槽位）必须是指针，锚定框架区或镜像区法卷的**某卷某节**。锚不到法源 = 法卷有覆盖缺口，走 `changes/` 立案补法，禁止就地自造形状（正面义务）。流程性内容（顺序、判据、工序、验收动作）不可机械化，住 skill 本树自带权限，不受此律——否则法卷被步骤污染、工作台被降格成链接目录，两头都失去宽严双份的本意。界线仍是那把尺子：这句话能机械化执行吗。检查落点 = `ddd-review` 的锚点抽查；不做机器全自动化（锚点解析度不足，硬做闸 = 误伤机），攒案例后再议。

## 3. 教学中立条款（D4 教义）

- 教学文档是通用抽取，不是业务镜像：代码围栏与反引号内的路径/类名禁 `order/Order/product/Product`。用通配 `{agg}`/`{Agg}` 或虚构教例家族（现行两族：Payment = 新建聚合教例，Reservation = 读写链路教例）；虚构类首现须标「虚构教例，sample 未实现」。`tutorials/` 是真实例操作手册，业务词豁免。
- **真实例指针位**（代码块外 + 标注）是全仓业务名合法位之一。
- 辖域：C4 扫 `knowledge/docs`、`.agents`、`knowledge/specs/current/`（法卷是严格件，形状必须中立）；`changes/`、`archive/`、`tutorials/` 豁免（案卷记录当时语）。业务契约住 `sample-application/specs/`，在扫描面外——其业务合法性由辖域保证；框架法卷依法使用框架词汇。
- 模板与框架 API 自洽即可，不整段编译验证（残余风险接受，判据：D4 裁决）。

## 4. 强制同步规则

| 触发 | 必须动作 |
|---|---|
| 改 `GlobalRestExceptionHandler` 映射 | 同 PR 改其 javadoc + `reference/api/common-exception.md` §2 表 + exception 法卷条款（C5 会红） |
| 改 `MybatisPersistence` 通道行为 | 同 PR 改其 javadoc + `reference/api/common-ddd.md` §2 + OL/BP 相关条款 |
| 重构包结构（sample/common） | 当天按 check-docs C1/C3 报告修全部指名文档行 |
| 新增/变更**框架行为** | 先立 `knowledge/specs/changes/<slug>/` 四件套（specify → plan → tasks → implement）；归档折叠进本区 `current/` |
| 新增/变更**示例业务聚合行为** | 先立 `sample-application/specs/changes/<slug>/` 四件套；归档折叠进本区 `current/<agg>.md` |
| 施工与验收（案卷执行期） | tasks 条项完成即勾；取证、AC→证据映射、delta 源回填、漂移回门一律记 `implement.md`（施工账本唯一载体）。范围要扩 → 回批准门并在 implement 漂移记录留档 |
| 修订法卷条款 | 同 PR 核对 docs 同题设计卡无矛盾；有矛盾改 docs（法卷赢） |
| 新设计决策 | 有案卷 → 本案 specify §裁决记录落条（表决行 + 当时理由 + Confirmation 收据，形状 → §1）。无案卷的"修码就法"裁决 → 所涉法卷"生效登记"节一行 + theory-map 账本一行。两类决策 theory-map 账本行都必同案齐落 |
| 案卷折叠入 archive 前（瘦身闸） | 逐件核查四件：两门收据齐（每案两停全落笔）、每一裁决有表决行与当时理由、supersede 宣告（若有）点名旧案在位裁决；条文正文只住 plan、账只住 implement。多句裁决理由只准住 §裁决记录（冻结快照）；"今天仍成立"的部分必经 ⑨⁺ 复写进解读架现行版 |
| 案卷折叠时（⑨⁺） | 本案裁决的沉淀论证同 PR 复写进 `docs/explanation/` 对应解读篇，篇脚回指 `→ 案卷 <date-slug> §裁决记录（决策快照）`；无同题篇则立篇并按登记法仅登记 docs/README 一处；事务性决策（不新增"为什么"）theory-map 一行账即算完成（防灌水）。划界判据：法生效后该理由是否仍成立且指导读法——仍成立 → 解读架有现行版；仅当时情境成立 → 留 §裁决记录作化石。存量不溯及、触发式随位收编 |
| 卷宗清册执行（两侧 `specs/archive/` 整册归零，含镜像区；`decisions/` 区已废并入案卷） | 七步仪式，SHALL 由独立清册 bill 承载：① **逐案再核表**（四栏：立因/取舍/被拒方案及拒因/生效边界 → 去向 = 解读篇某节某段，或判"纯史件，随灭"；表随 bill 递交，缺案缺栏则批准门不得通过）② **补沉淀**——再核发现因果缺口，同 bill 内先复写进解读架（⑨⁺ 的追溯执行）③ **整袋删除**（whole-directory/whole-file，禁拆件）④ **净账**——README 账行同裁，两册 README 回到空壳章程态；镜像区 archive 若无 README 则补立空壳章程（git 不存空目录）⑤ **净面**——全活面 date-slug 案名删除或转无编号散文（含页脚快照账行整行删、法卷生效注转年份散文）；`ADR-`+数字属常设零容忍不待清册；C1 验零幽灵 ⑥ **连带**——计数宣称、glossary、docs README、theory-map 账本同步 ⑦ 七闸绿（C6 清册臂 + 空册自洽 + check-diagrams + `mvn compile`）。**清册 bill 自焚**：不折叠、不落 §裁决记录（执行非裁决事件），末步整删自身案卷目录——三区零残留 + C6 自焚识别过闸是唯一合格终态；批准凭据 = 审议期 diff 中可见的再核表，阅后即焚是审计件的正当归宿（法不考古） |
| 新增文档 | 仅登记 `knowledge/docs/README.md` 一处（唯一索引；伞 README 只写三态法律） |
| 新增规范行（必须/禁止） | 只能进法卷（走 `changes/` 程序）。`.agents/` 内禁止出现裸法条——方法区不载地图亦不载法 |

## 5. i18n 错误码管理

- 格式 `{aggregate}:err.{scene}`。messageKey 是前端渲染位点，服务端不维护 messages.properties；条款 → [EV-2](../../modules/exception.md)。
- 全仓 key 清单的唯一登记账本 = `knowledge/docs/how-to/error-handling.md`（登记簿居设计卡，形状条款在法卷）。禁硬编码可读文案作 key。

## 6. 防复发

- `knowledge/scripts/check-docs.ps1` 七校验（说明唯一入口 `docs/reference/doc-guards.md`）：PR 门 changed-files-only、夜间全量；`ddd-review` 末步必跑，非零即返工。
- 豁免清单外置 `knowledge/scripts/check-docs.whitelist.txt`，新增豁免须 PR 评审写理由——清单只删不增。
- 被 check-docs 抓过、或审计定过性的写法，在 §2 归属表增行，不另发明新载体。
