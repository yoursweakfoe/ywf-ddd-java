# 案卷形状修正案：三件套 → 四段制（Specify → Plan → Tasks → Implement）
- Slug: 2026-09-sdd-four-stage ｜ 日期: 2026-09-10 ｜ 关联 ADR: ADR-0003（③ 裁决当刻落卷宗：四段 SDD 采纳、supersede 两阶段批准判例）

## Why（为什么现在改）
现行三件套（proposal → spec-delta → tasks）相对业界 spec-driven 标准链（Kiro：Requirements→**Design**→Tasks→Implement；Spec Kit：specify→clarify→**plan**→tasks→implement）缺一个「怎么做」的正典位——设计事实无处栖身，被拆散寄养三户：机制条款混进 delta 的 SHALL、参数决策塞进 tasks 条项、施工取证与验收映射无账可落。本案卷两封活体自证：p6spy 案 spec-delta 背了「runtime scope、版本 pin 策略文件」（设计事实冒充行为事实）、tasks 第 4 条塞了整串 spy.properties 键值（施工图混进验收清单）。后果：三层无接缝、批准门只有一道半（两阶段批准靠判例打补丁而非常法）。

## What changes（行为级，为谁改）
主体 = 立法者（开发者＝项目主）与执法 worker（agent）：
- 案卷工作台上三件升四件，一份一身份：**Specify** 定「做什么/为什么」（用户故事、验收标准、约束）；**Plan** 定「如何构建」（技术形状、修卷 delta——改法动作是施工计划的一环）；**Tasks** 拆离散可验证任务；**Implement** 记账执行与逐条验收。
- 批准门明文化分档：Specify 门（验收即法条草案，必硬停）→ Plan 门（方案+修卷量，施工闸门）；两阶段批准旧判例入法为常制。
- 法域既有骨架不动：三类件分家、折叠即修法、审议稿随便改/current 为准、两册到期归零制（→ 归属法 §1「卷宗清册制」注）、宽严双份——四段制只重排**案卷内部**的文书分工。

## 验收标准（AC 账本 = 人话摘要；法条正文唯一住 plan §2，折叠时入各卷）
- **AC-1** 案卷 = 四件：`specify.md / plan.md / tasks.md / implement.md`；形状权威 = `_template/` 四文件（旧三件模板汰换）。
- **AC-2** specify 只载问题与验收：Why / What changes / AC-n 账本 / 约束 / 不做 / 待裁问句；零实现细节、零法卷条文。
- **AC-3** plan 只载如何构建：技术决策（编号 P-x，含被拒替代案）+ **修卷 delta**（ADDED/MODIFIED/REMOVED，法条正文唯一居所，每条映射 AC-n）+ 影响面与回退。
- **AC-4** tasks 纯执行清单：条项 = 一个可验收动作，条内**零设计参数**（参数一律指回 plan P-x），尾巴映射 AC-n。
- **AC-5** implement 执行账本：逐条勾验（完成即勾、禁攒批）、取证记录、AC→证据映射表、delta 取证源回填账、漂移记录（范围扩→回门）、折叠收官闸。
- **AC-6** 三写禁绝（单一抄本）：行为问题只住 specify、法条正文只住 plan §2、决策参数只住 plan §1、执行记录只住 implement——同一文字全文案卷内恰出现一次（指针不算正文）。
- **AC-7** 门制入法：批准门 = Specify 门 → Plan 门两档，**每案两停、不论案之大小**；法面不设并审或免停条款——放行豁免只存在于会话中项目主的明示指令（法条刚性、出口在对话，2026-09-10 项目主拍）；「两阶段批准」旧判例行从章程中 REMOVED，由常制条文接管。
- **AC-8** 波及面随动：全仓法案义「三件套/spec-delta/proposal」表述 25 文件逐处改写（plan §3 对照表枚举），泛称「三件套」（CQE 三件套/职责三件套等非案卷义）**零改动**；折叠当刻执行（归属法 §4：docs/章程随动只在折叠时点）。
- **AC-9** 执法器随法：`check-docs.ps1` C6 清册臂案卷文件名依赖（`proposal.md`）换 `specify.md`，doc-guards 说明同步，切换后七闸全绿。
- **AC-10** 图与锚表随动：`drive-relations.d2` 工序标签四处 + `knowledge/README.md` 锚表对应行改写，render/check 双闸全绿。
- **AC-11** 历史不回改：`archive/` 既在案（2026-09-archunit-rule-doc 三件袋）与审议中 p6spy 案卷不为本案回溯改写；折叠后案卷形状条款加「案卷形状随立案时模板，在位不回改」一句。
- **AC-12** 镜像区随动：`sample-application/specs/` 两处援引行同步四件措辞（模板两区共用，法只立一处）。

## 约束
- 辖域 = 框架区流程法（`knowledge/specs/`）；镜像区只随援引行，不另立法。
- 本案自举：审议稿按四件形状起草（changes/ 审议稿随便改 + 模板形状权威尚未改，无撞法）；审议期**不碰 `_template/` 本体**，模板正文四件全文住 plan §4，折叠日一次换装。
- 零 Java 代码触面（唯一例外：check-docs.ps1 开关，属执法装置非行为）。
- 新法生效时点 = 本案折叠；此前现行法仍是三件套。

## 不做（范围边界）
- 不设 constitution.md 独立件（本店宪法 = AGENTS 九条 + 法卷，已存在且归属法 §1 钉死）。
- 不设 clarify.md 独立件（澄清 = specify「待裁问句」节，现行形状保留）。
- 不动 archive/ 本体与 decisions/ 既有卷宗（在位不改；新裁决 = 新立 ADR-0003）。
- 不重塑 p6spy 案卷（用户令挂起；本案折叠后由该案自己的审议期收编新形状，属它自己的工序）。
- 不改八步工序（①–⑧）与 ③⁺/⑦⁺ 论证沉淀边——四段是 `changes/` 容器内部结构，与决策事件流正交。

## 裁决记录
- **Q1 门档弹性** ✅ 已裁（2026-09-10 项目主）：**每案必两停，不论大小**。理由一句：流程规范必须严格固定；「不想停门」属会话层人类明示意图，非法面条文例外——法面刚性，出口在对话。（裁决入法 → AC-7 / plan P-4；论证快照 → ADR-0003）
