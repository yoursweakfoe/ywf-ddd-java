# 提案：案卷与判例卷宗分家（过程归案卷，论证归卷宗）

- 状态：审议稿（待批准）
- 立卷：2026-09-09
- 辖域：框架区元法（归属法卷 §1/§2/§4）+ new-bill skill 工序指针 + 两区 README 地图随动
- 触发：用户体感「archive 里看到的好像也是架构决策」→ 归属法 §2 现表对**案卷内裁决论证**与 **ADR 决策论证**无归属行，两栖=双写漂移温床。

## 问题（现状病灶实证）

1. 同一条裁决的论证在**案卷与判例各抄一遍**：`archive/2026-09-common-it-consolidation/proposal.md` 末表「Q1~Q4 裁决 + 理由」与 `ADR-0035` Content/Decision Outcome 近乎全文重复；pg-native 案同态（proposal 五问裁决 ↔ ADR-0033/0034）。
2. 归属法 §1 L12 与 §2 L29/L30 只钉了「架构决策→decisions」「需求/行为规格→specs」两个 home，**未裁「立法过程事实」（表决、批准、任务勾验）的 home**——于是案卷顺手收编论证，判例区又必须复述背景，边界靠手感。
3. 违本仓元法自证：归属法总纲「每类事实恰好一个 home」——「决策为什么成立」这句话现在有两个家。

## 裁决主张（元法三行）

- **R1 判据入典**（归属法 §1 分域注 + §2 增行/改行）：案卷（`specs/changes|archive/`）记**立法过程事实**——问题陈述、条款变化量（delta）、**表决行**（何人何时批/否/裁何事，一行制）、施工任务勾验；折叠即使命终、入档封存。判例卷宗（`decisions/`）记**决策论证本身**——context / 取舍 / consequences，跨时间被引（新判例前查旧案、supersede 依赖旧论证）。同一事实双栖者：**论证归卷宗、过程归案卷**，案卷涉已立 ADR 之决策只准「表决行 + `→ ADR-NNNN` 指针」，禁复写论证正文。
- **R2 折叠前瘦身闸**（归属法 §4 增触发行）：案卷入 `archive/` 前逐件查 proposal——凡多句决策理由，若该决策应立判例而未立 → 先补 ADR 再折叠；案卷本体裁至表决行 + 指针。
- **R3 工序随动**（new-bill skill 步骤 3/6 各挂一句指针，零法条纪律：正文在归属法，skill 只指路）；`specs/README` 目录表 archive 身份句、`decisions/README` 本区法律句各补分家一句（地图随动，非条文）。

## 边界与不办

- **不溯及**：archive/ 既成案卷与旧 ADR 双写现状一律不回改（判例区 append-only、案卷区只进不改）；新法自本案折叠起向后生效。
- 不新立 ADR：本案是元法（立法技术）修订非架构决策，归属法自身即 home；裁决过程事实（本提案表决行）住案卷。
- 不动 C1~C7 工具：机器化「禁复写论证」需语义比对，超出现有闸能力，硬做=误伤机（判例：实施内容基准律同款「机器全自动化暂缓」），落 ddd-review 人肉锚点抽查面。

## 表决位（2026-09-09 已裁决，本卷即新规自我执行首例）

Q1 批准 R1~R3、Q2 采「表决行至多附一句因」——用户裁：「按推荐来」。论证正文从此住本提案与 ADR 分家诸条，案卷此后只登表决行。
