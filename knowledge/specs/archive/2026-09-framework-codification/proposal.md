# Proposal：framework-codification（一期：api 字典架规范入法）

## Why

宽严双份裁定（2026-09-06 用户决议）：规定性「使用方式」文字在 Diátaxis 四象限里没有执业执照——reference 的本分是描述性字典（"准确完整描述技术细节"），how-to 的本分是任务菜谱。而「你应当这样用框架」是应然句，应然句在四态中唯一合法容器是 specs（代码跟它走）。现状这些规范寄居在 docs（代码变了它被动跟），一旦代码漂移，"保证"二字会被地图守则溶剂掉。

## What

把 8 篇框架模块文档（`reference/api/common-*.md`）的 §3「使用方式」节**整节入法** → `knowledge/specs/current/{module}.md` 八卷；原节瘦身为宽松件（法卷指针 + 原导语，若有）。零新增规范内容——纯入法。

## 不做什么

- how-to 架的规范入法：二期独立法案（`2026-09-howto-codification`），待本期体例认可
- 业务镜像区两册：不动（辖域已合法）
- api 文档其余六节（定位/类表/依赖/原则/决策指针/边界）：字典与论证本体，留守
