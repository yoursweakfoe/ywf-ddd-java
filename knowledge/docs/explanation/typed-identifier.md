﻿# 类型化身份——把「拿错 ID」从运行时拖进编译期

> 本页回答一个问题：聚合身份为什么从裸值换成每聚合专属的终类型，以及这道墙为什么只砌在写侧。条款权威在法卷 → [blueprint 法卷 BP-13~BP-17](../../specs/current/patterns/building-block/aggregate-blueprint.md)、[写链法卷 WC-13](../../specs/current/patterns/chain/write-chain.md)、执法是 ArchUnit R15（锚 [common-test.md §2](../reference/api/common-test.md)）。本页零条款零形状，只讲道理，冲突时法卷赢。

一句话先给全文答案：本框架经裁决不载事件管线与长流程机制，词汇层的编译防线因此是框架侧余下收益成本比最优的增量——一次定型、零运行期机制、零 bug 膨胀面；而墙的砌法处处克制：币种不过流通域界，类型不站验货岗，防线不与 javac 重复开工。

## 为什么是现在这块砖

各聚合的 ID 在类型系统里同形——全是裸 UUID。把 A 聚合的 ID 递进期待 B 聚合 ID 的调用位（跨聚合编排传参错位、批量结果复用进错仓储），编译器无从察觉，错误迟到运行时才暴露。防这类错的备选本来有一排：事件溯源、Saga、运行期校验切面——全部要付机制成本，且前两个方向早被实践裁决毙过（实现面代码膨胀、bug 面失控，场景自持为纲）。词汇层防线是排除它们之后**唯一免费的那档**：record 终类型是纯 Java，发行一个 `Identifier<V>` 接口做类型学锚点，之后的一切由 javac 白送。裁决 Q2 在「发接口」与「纯命名约定 + 按 `*Id` 名执法」之间选了前者，因为按类型执法有硬度、javadoc 有锚，按名字执法会随改名蒸发。防线的全部成本 = 每聚合一个 record + 入口一行 `of(...)`。

## 币种流通域：墙只砌在写坏级的门口

类型化币种的范围裁在写侧全程：domain 的身份槽与跨聚合引用槽、application 写侧的 Handler 局部、DTO、DomainService 签名（Q1 裁「边界内路线」）。契约 CQE/CO、PO、读侧端口与读 DTO、聚合内子实体 PK 一律维持裸值——豁免面是法卷 BP-15 的明文。

两头各有各的理。**契约不外露**：对外主要对接前端程序，即便对方也是 DDD 化系统，不保证沿用本方命名，撞名仍须重封装——类型外露无净收益，wire 与 OpenAPI 形态因此逐字节不变。**读侧不入**：根据是宪章不是权衡——RC-6 读端口禁泄漏 domain 类型，项目主裁语「绕过了 domain 的读侧，它就是不应该依赖 domain 里的内容」（Q6），本案对 id 包不开任何新例外。混放残余风险（读端口两枚裸 UUID 互换）登记在册、随姿势接受：读错是 404 级难堪，不是写坏级灾难。币种在哪一层流通，错就在哪一层最贵——墙跟着钱走。

## 装箱不站岗

`{Agg}Id`（教例 PaymentId，虚构教例，sample 未实现）的紧凑构造器只做 null 检查：不复验格式、不查 UUID 版本位（Q5）。三条理：**非法格式到不了此处**——Web 层类型转换对坏值已 400 判例在先；**存量行必须照过 `of()`**——装载路径若逐条校验版本位，等于炸掉一切历史数据与手工插入行，任意版本装载照过的反证测试已入执行账（案卷 implement §1 条 4）；**出生保证另有其主**——合法性在铸造入口（`AggregateIds.mint()` 与三来源通道）一次办结，类型只是容器。这与当年毙掉 MyBatis-Plus 运行时拦截器是同一把尺：框架发行角色词汇，不提供运行期魔法；校验放在铸造点是人能读到的代码，塞进构造器就变成没人记得的暗规。身份来源三分法（应用铸造 / 自然键 / DB 代铸，机制不绑底层类型，Long 承载照样成立）住 BP-16；非聚合持久对象的豁免住 BP-17——不强套聚合套件、不为过铸造假主键。

## 一条防线立一处：F 边界勘获与等式臂备胎

施工时点（implement §4）发现：负证明探针原定的第四锁「端口-根槽不一致必咬」**在 javac 里根本构造不出来**——框架既有泛型界 `Repository<Domain extends Identifiable<ID>, ID>` 早已把「端口 ID 槽 = 根 ID 槽」锁进编译层。于是 R15 的一致性等式臂当场降格：它守的不再是敞开的门，而是裸继承、类型擦除这类逃路，是防御备胎。审议稿随即随改，记入漂移账——这是事实修正不是裁决。

这一勘获是全案最干净的一课：**规则不重复 javac 已强制的事**。一条防线立一处，两处立同一道防线就多一处腐烂位；ArchUnit 的钱只花在编译器看不见的地方（身份槽必须实现 `Identifier`、豁免位不许误伤），编译器管的事一律让位给编译器。

## 废号顶位与插位重排：编号是教义锚点，不是历史文物

新执法规则取号 R15 时撞上在册废号——旧 R15（禁某 ORM 增强库）此前已废止留账，模块卷旧文还写着「编号永不复用」。项目主裁语：「没有永不复用这种说法，占位缺失就顶上」（Q8）。裁定落地为两半：旧作废账**原位保留一字不改**（账住 [architecture-rules.md](architecture-rules.md)「废止也是账」段），新语义顶位接管该号；TR-1 编号纪律随之修典。理由一脉相承：文档、评审、提交信息全都拿编号互指，要的是锚点稳定，不是历史序列的博物馆式完整——坑空着才是对读者的失责。

同一教义管着槽位号（Q7）：新件 `{Agg}Id` 插位为 ⑫、原 ⑫–㉒ 全体顺移，不挂末号——因为身份先于根被引用，阅读序 = 依赖序，一致性优先于小 diff。顶位与重排是一枚硬币的两面：编号永远服务「现在怎么读、怎么执法」，不服务「当初怎么发生」。

## 被拒清单：哪些门根本没敲

- **jMolecules 制品**：借 `Identifier` 词汇思路，不借 jar——框架惯风是只发行角色词汇，多一条依赖边就多一份供应链责任。
- **phantom 泛型 `Id<A>`**：单泛型靠标签类型区分聚合，类型擦除下 A/B 互赋编译照样放行——假安全比没安全更贵。
- **抽象基类路线**：record 无法继承类，基类即判 record 死刑；而 record 的值语义正是身份类型要的。
- **`{Agg}Id` 嵌套进聚合根文件**：跨聚合 import 必须只见 id 包、不见根类——引用一个 ID 不该拖进整个聚合。
- **读侧同步类型化**：正面撞 RC-6 与「读绕过 domain」教义，见上节。
- **框架代劳自动转换**（全局 Converter / AOP / Jackson 直灌）：即当年毙 MyBatis-Plus 所拒的运行时魔法，不可两面标准（Q3）；显式 `of()` 单点、可 grep、可测。
- **给 DddMapper 加身份泛型**：把写侧币种渗进持久契约，豁免面自破（P-4）。
- **为 DB 代铸预建号段/雪花设施**：为尚未存在的需求立法，是事件管线病灶的翻版（Q4 裁「不为未存在的聚合开洞」）。

## 一把尺子

全案八问其实共用一句判据：**错误在它最贵、而机制又能免费咬住的关口砌墙，其余一律不开例外**。编译期拦得住的错不花钱立运行期检查；类型该流通的域止于风险变贵的那道门口；合法性在出生点办结，容器不复验；已有一道防线立着的位置，第二道只配当备胎或干脆不建。拿去量下一个「要不要加层机制」的问题，先问：javac 能不能白送这一口？
