# 模式法卷为什么是十摊（解读 · 摆架 rationale）

> 本篇回答"为什么这样摆"；"归哪摊"的裁决判据住法卷 → [摆架法卷](../../specs/current/patterns/meta/pattern-taxonomy.md)。冲突裁决：摊归属之问法卷赢，动机之问本篇为据。→ 案卷 2026-09-pattern-taxonomy §裁决记录（决策快照）

## 1 · 病灶：目录不答任何问题

2026-09 之前，`specs/current/patterns/` 十五卷平铺：新卷落哪凭默契，摊概念（写链/批量是一家、并发/分布式是一家）只活在对话里。而秩序其实早已存在——只是全住别处：`_template/` 四式管**卷形**，条款前缀管** namespace **，how-to 卡与 skills 管**任务路由**，prohibitions 节序管**分层**。病灶准确说是：目录本身不承载任何一根轴。

## 2 · 候选轴从哪来：六源扫描

分摊方案不从感觉来，从权威模式库的分类实践中来（外部调研，逐源核对一手目录）：

| 来源 | 它的分架轴 | 组数 |
|------|-----------|------|
| Gamma 等《Design Patterns》 | purpose（创建/结构/行为）× scope 双轴表；目录只用一根 | 3 |
| Evans《DDD Reference》2015 | 按工作阶段四部 + 按关切再分六节（基本构件/灵活设计/上下文映射/蒸馏/大规模结构） | 6 |
| Vernon IDDD | 无印部分；作者自述按构件依赖序排章 | 14 章 |
| Fowler《PoEAA》 | 应用架构部位：领域逻辑/数据源/ORM 行为/结构/元数据/Web 表现/分发/离线并发/会话状态/基础模式 | 10 组 |

## 3 · 两根轴为什么出局

**任务轴出局**（宜家样板间式："要加用例走这排"）：这条轴本仓已完整实现过——12 个 skills 一个技能=一个施工时刻，how-to 十三卡"任务→设计卡→governing 法卷"。伞 README 的既有裁决（法律按身份分架、Diátaxis 只管地图区）+ 归属法"一类事实一个家"合起来宣判：法卷目录再排一次任务路由=同一份导航图印两处。

**层轴出局**（按 domain/application/infrastructure 分架）：十五卷里链卷天然横跨四层，分架等于拆卷（违法卷条文唯一住所）；且层轴已被 prohibitions 的节内分域消化过一次。Fowler 目录里"基础模式"独立成组的存在，恰恰证明横切纪律需要非层级的家。

**卷形轴**（元法/构建宪/通式/禁令表——`_template/` 四式的暗示）成立但不当目录：它是立法者视角（"我立哪种卷"），不是查卷者视角（"我碰哪摊事"）；GoF 的做法是页眉印形、目录单一根轴——本仓的对应物：形住 `_template/`，轴住路径。

## 4 · 十摊的形状：关切为架、粒度裁决四题

留下关切轴后，真正的争论是粒度。裁决史（详见案卷裁决记录）：

- **契约摊蒸发**：拆开是三个问题——文书格式随用处（入口出口→链路、模块构成→构件）、事后能否改→外交。"都沾边"恰证明它不是话题是产出物。权威旁证：Evans 把 Published Language 收在上下文映射节，Fowler 把 DTO/Remote Facade 收在分发组——没人给文书单开设架。
- **性能摊撤除**：预算条款（分页上限、批量上限、N+1 禁令）各有东家卷，是正身不是寄居；防护条款（超时重试熔断）是"和外人打交道怎么防翻脸"，收进边界摊；运行账单话题归部署与运维。微软 AWS 设性能支柱是因为他们管运行，本框架管码形状。
- **协作拆内外**：对手在不在自家进程内是真界线——院内（跨聚合、并发写者）事务与线程语义，院外（跨服务、外部系统）网络与方言语义。
- **入口并链路、可观测并部署、分层并总论**：第一环不独立成环；"被看见"不独立于"跑起来"；公理级条款集收进地基。

十摊由此落定，摊间界线各写死在摊卡（法条正文，改字立案）。

## 5 · 迁都记：从名册到路径

方案本可停"逻辑分架"（README 名册、文件不动）。项目主裁定升级：**摊进路径、名册裁撤**——目录树即户口，"ls 即对账"；空穴摊预建立牌（有牌无肉，洞登记在法卷带证据）；四宗条款搬家当场动肉，采**原号随身**：WC-1 迁到哪仍叫 WC-1，全仓引用零断链，新铸编号一律摊名式（meta-、data-access-…）。外部先例：Evans 书按工作阶段排部、Reference 按关切重切六节而模式本身不换名字——组织的轴可以换，身份不重铸。
