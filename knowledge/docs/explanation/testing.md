# 测试为什么长成这样（机器红线与真实基座）

> **本页=解读架的"为什么"**：回答这套框架的测试为何是现在这副样子：架构靠机器守护不靠人眼、规则集以常量消费、库一律真 PostgreSQL、框架自测聚进一座试验场。一切条款、形状与验收清单的权威在 [测试符合性法卷](../../specs/current/patterns/discipline/testing-conformance.md)（严格件），选型指引在 [设计卡](../how-to/testing.md)。本页零条款零形状，只讲道理，冲突时法卷赢。

## 分层教义靠机器执法，不靠记性

结论：DDD 分层约束直接编码成 ArchUnit 测试，执行点是 CI；违规即构建变红，法条与执法者是同一份代码。

分层约束如果靠人工 review，等于把红线押在人的记性和客气上，而纪律约束不可依赖：人会忘，更会豁免，每一次"就这一次"都在拆教义的台。CI 才是红线的自然执行点，这里没有讨价还价的中间人。

这套选择带来三个至今成立的配套品味。**规则编号是教义锚点**：每条规则带一个稳定编号，文档、评审、提交信息都拿它互指；锚点永不重排；废号留账原位、占位缺失可顶（2026-09 R15 先例）。红线必须有名字，指得出才守得住。**护栏自己也要被证明活着**：规则库经历过"谓词相邻段匹配、断言面永远为空"的死规则事故，于是每条规则配上违例必失败的负证明。能拦住车的护栏才存在，挂在那里不动的只是装饰。**覆盖不到的要诚实登记**：不是所有教义都能机械化，时间类型、返回值形状等就查不了；规则覆盖不到的，在规则集类头"已知缺口"如实登记。承认缺口，好过假装全图。

框架自己的包也被同一套规则扫描。守护对双方架设，执法者不自外于法。

## 规则的消费面就是一个字段名

结论：框架规则集以公开静态常量暴露，业务挂载动作只是引用常量。

规则定在框架里，业务服务怎么拿走？备选是基类或装配工具，即继承之或调用装配方法。裁决选了更小的消费面：**公开静态常量**。业务测试类直引框架常量即完成挂载：没有继承层级，没有配置文件，引用处所见即挂载本身。组合优于配置在这里的具体形状，就是"一个字段名吃掉全部装配"。

单源消费换来一个硬承诺：**消费方零重复定义、零本地谓词覆写**。历史上曾因包命名相撞，业务侧被迫本地覆写规则绕路。根治之道不是保留覆写权，而是把病灶（包名保留段的歧义）在框架单源处修掉，然后把本地例外全部收回。要改规则就去单源改：修改路径唯一，腐化没有旁门。

规则集**内部**怎么设计：红线图分几块、类型锚点与包段匹配各管什么、空集通过这个弱点为何被容忍、缺口账上挂着什么，是另一篇专论 → [architecture-rules.md](architecture-rules.md)。

## 测试必须直面生产方言

结论：真库基座全仓唯一，方言层不残存，豁免句作废。

早期契约是"测试档用内存数据库、零基础设施前置"，听起来便宜，利息付在两头。**方言永远隔一层兼容模式**：兼容层跑绿，不等于真方言跑绿；手写的 SQL 恰恰在最需要实证的地方只拿到二手证据。更坏的是反向侵蚀：兼容库的脚本习惯会反哺产库设计，让测试的将就决定生产的形状。**框架与示例两套基座互相打脸**：示例先真库化后，"容器测试只走真库"的普适条款与框架自测仍居内存库的现实，只能靠辖域豁免句缝补。法卷自我矛盾是法需要修的气味，不是现实需要绕的许可。

活下来的配套裁决同样清楚。**测试不建表**：库形状权威居迁移工程，一份形状一个作者，测试只消费形状。**隔离双轨**：容器测试默认事务回滚；真 HTTP 链教例独立提交、回滚够不着，以类级清场语句重置。隔离可信的前提，是承认不是所有写入都回滚得了。**逃生门不做**：不引入"无库自动起容器"的便利，改为在 README 记一条显式前置。演示契约从"零前置"改述为"零网络出口、一条前置、全量绿"。前置摊开讲，比藏进测试代码更诚实：读绿的人应当知道绿是在什么地面上长出来的。

## 框架测自己，搬进一座试验场

结论：新建第九个模块作试验场，一切框架自测集中住这里。

真库化之后，框架诸包的测试若散居八个发布件，就要在八个 POM 里各养一套测试栈，且没有一个地方能把"框架全家"放进同一个真实环境里跑。试验场的裁决因此成立：一切框架自测含单模块独立单测集中住这里；主源码永空置、不发布、不受"发布件测试依赖最小化"义务约束。library 们的 POM 借此清零，测试栈不再散居。

试验场的运行哲学和它的名字一样：**从零人工前置，跑即实证**。专属测试库由支撑类三段生命周期自管：裸连维护库自建数据库；每个 JVM 启动时重建专属 schema 并执行形状脚本；退出时清空。轮与轮之间零残留，实证过。

几个细节全是品味。schema 用全称拼写而不缩写，"我们不缺这点长度"：名字说清楚永远省过打字。"空库"教例从戏法改为**真空 schema**：旧戏法是同一连接串不跑初始化脚本；新教例是同库双数据源、异 schema，表的可见性由数据源配置裁决，形状脚本一律不写限定名。教路由就用真空库教，假教例教假语义。迁卷保持与被测类全同包名：跨构件同包是 classpath 时代的合法刻意技术，白盒访问零扩大，**绝不为了搬测试而放宽产码封装**。

回报在施工当日即到。全家上同一真基座后，跨模块组合污染当场显形：监控组件的自动装配混进一切上下文；安全组件在纯持久化上下文里缺件爆炸；异常兜底与鉴权组合时把 403 吞成 500。这类缺口在各自兼容模式里自说自话的时代根本测不出来。试验场不是把文件搬个堆，是**把组合的真话逼出来**。代价不过是两条，都在账上、不是暗债：跑框架测试需要数据库常驻（与示例同一条前置）；同包跨构件在将来启用模块化时须重审。

## 一把尺子

四条裁决其实是同一句话：**别让"绿"冒充它不是的东西**。规则配负证明，是让绿有牙齿。消费面收成一个字段名，是让绿单源可溯。库要真、前置要摊开，是让绿站在生产同款地面上。测试聚进试验场、每 JVM 复位，是让绿出现时场景干净、组合真实。这套框架把"测试即验收"当前一等公民，验收的可信度就押在这四件事都机器可证上。
