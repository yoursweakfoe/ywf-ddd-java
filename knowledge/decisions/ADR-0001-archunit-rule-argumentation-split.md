# ADR-0001: ArchUnit 规则集论证载体分工——javadoc 收挂载契约、论证迁解读架、编号纪律上收法卷

- Status: Accepted
- Date: 2026-09-10
- 案卷：`knowledge/specs/changes/2026-09-archunit-rule-doc/`

## Context（当时快照）

`DddArchitectureRules`（893 行）的类 javadoc 承载着规则集的全部设计论证：五块分工哲学、类型锚点 vs 段匹配、空集通过机制、包命名税迁移史、缺口裁决账。项目主判定「规则设计相当不透明、可读性依然很差」。归因审计：这不是文笔问题而是**载体错位**——归属法 §2 明示设计论证 canonical 住 `docs/explanation/`，现状是解读架只有 testing.md 总纲、专项论证寄居代码面；且 R 编号稳定性、载体分工两条规范行是法卷外裸法，无机器背书。判例先行：历元二空册，无撞案。

## Decision（裁决三问与拍板）

- **问 A 载体**：新立 `docs/explanation/architecture-rules.md` 专论。→ 项目主裁「按推荐」。被拒：并入 testing.md（一篇一问的总纲被专项论证破坏，体量失控）。
- **问 B 瘦身深度**：**中档**——类头「空集通过警示 / 已知缺口」两节降为一行清单（详情全部迁架），模块地图、扫描入口、编号纪律句保留；逐常量 javadoc 收四栏最小契约（守护什么 / 怎么判一句 / 挂载 / 空转或局限）。→ 项目主裁「中档」，知悉并接受其风险（改规则者须翻架方见红线图全貌）。被拒：轻档（类头仍堆全文论证，搬家不彻底）；重档（剥掉挂载契约，代码面看不见任何红线，违背 TR-2 初衷）。
- **问 C 上收法卷**：TR-1（编号稳定性）/ TR-2（论证载体分工）/ TR-3（缺口登记账）折叠入 `modules/test.md`「规则集治理」节。→ 项目主裁「按推荐」。被拒：法卷不动（javadoc 瘦身后裸法义务反而失去唯一载体）。

## Consequences（当时推论）

代码面缩为可导航契约面；论证获得唯一现行版居所；规则修改的同步义务变两条（javadoc 四栏 + 解读架对应节，TR 条款执法）。接受风险：中档下类头只余一行清单，「红线图非全图」的警示靠 ddd-review 与法卷条款兜底。连带修复三处过期互指（javadoc 残引 `.agents/rules/0X`、domain.md「A2 白名单」、common-contract.md「见类头」对照表）。
